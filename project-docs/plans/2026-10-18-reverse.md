# Bank mode: a small reverse at the bottom of the Speed stick

## Context

In BANK the Speed stick has no reverse: its bottom brakes to a stop. Up against a wall, the pilot has no way to back off without yawing round. The owner wants the bottom of the Speed stick to give a small reverse. It has to stay off at arming, because the stick sits at the bottom then.

Decided with the owner (2026-10-18):
- **Zone**: the raw throttle below `min_check`, which is the bottom 5% at the default 1050. `rcCommand[THROTTLE]` already flattens this band to 0, so nothing in BANK uses it today. The Speed law above `min_check` doesn't change, and the stop sits at `min_check`.
- **Reverse speed**: full reverse is 10% of `bank_mid_speed`. That is the lower half's speed line carried on below the stop with the same slope: 0.05 g of drag at the default, about 2 m/s on the sim's five inch. No new setting.
- **Braking**: pulling to the bottom from speed brakes exactly as hard as today (the 30° cap binds either way), then carries on into a gentle reverse. To stop in place, the pilot holds the stick at `min_check`.
- **Lockout**: reverse is off from arming until the Speed stick has been raised above `min_check` once. It locks again on disarm and whenever BANK re-engages, because `bankState` is cleared then.

## Changes

### `src/main/flight/bank_mode.h`
- `bankInputs_t`: add `float reverse;  // throttle stick below min_check, 0..1, 1 at the bottom`.
- `bankState_t`: add `bool reverseReady;  // the Speed stick has left the reverse zone since arming`.

### `src/main/flight/bank_mode.c`
- New constant `BANK_REVERSE_STICK 0.05f`: how far below 0 the reverse zone carries the Speed stick. At the lower half's slope this gives 10% of mid speed.
- `bankTargetSpeed()`: clamp to `[-BANK_REVERSE_STICK, 0.5]` instead of `[0, 0.5]`, so a negative stick is a rearward speed target. Update its comment.
- `bankSpeedForce()`: clamp the stick to `[-BANK_REVERSE_STICK, 1]`. The bottom-third brake branch and the lower-half path already handle a negative stick and a negative target, and `bankThrustVector()` already limits a rearward force to the 30° brake angle.
- `bankCompute()`, after the existing `tiltLocked` block, which keeps working on the stick at or above 0 so its "speedStick == 0" unlock is unchanged:
  ```c
  if (!in->armed) {
      state->reverseReady = false;
  } else if (speedStick > 0.0f) {
      state->reverseReady = true;
  }
  if (state->reverseReady) {
      speedStick -= BANK_REVERSE_STICK * constrainf(in->reverse, 0.0f, 1.0f);
  }
  ```
  While `tiltLocked` holds, `speedStick` is forced to 0, so `reverseReady` can't latch. `bankLookIntoTurnOffset()` already takes `fmaxf(speedStick, 0)`. `DEBUG_BANK` 1 (target speed) goes negative in reverse. No new debug field, per CLAUDE.md.
- `bankModeUpdate()`: fill `.reverse` from the raw stick, `(mincheck - rcData[THROTTLE]) / (mincheck - PWM_RANGE_MIN)`, clamped to 0..1 and guarded against `mincheck <= PWM_RANGE_MIN`. Uses `rxConfig()` (include `pg/rx.h` if `rx/rx.h` doesn't already pull it in). Radios that bottom out below 1000 (ELRS at 988) just clamp to 1.
- Header comment: replace "No reverse." with one line on the reverse zone and its lockout.

Unchanged: arming (`calculateThrottleStatus()` reads the raw stick, which is still below `min_check` at the bottom), `bankModeIsThrottleLow()` (collective), the ball and turn feedforward. Both flip sign for rearward travel already, as kept in the rewrite.

### `src/test/unit/bank_unittest.cc`
Follow the existing property-test style (`centredInputs()`, `computeN()`):
- `TargetSpeedCarriesOnBelowTheStopAsAReverse`: `bankTargetSpeed(-BANK_REVERSE_STICK, mid) == -0.1 * mid`, with the same slope as the lower half. `bankSpeedForce()` at full reverse from rest is rearward and within the 30° brake force.
- `ReverseOnlyAfterTheSpeedStickHasBeenRaisedSinceArming`: armed, `speed = 0`, `reverse = 1` gives a pitch target ≥ 0 (no reverse). Then a few frames at `speed = 0.2`, back to `speed = 0, reverse = 1`, gives a nose-up pitch target (rearward force). Disarm and re-arm, and it's locked again.
- `EngagedWithTheThrottleLowNoTiltUntilTheBankStickIsCentred` should still pass. Extend it with `reverse = 1` so it shows the tilt lock also holds the reverse off.
- `UpdateReadsTheReverseBelowMinCheck` (only if the test's stubs already provide `rxConfig()`/`rcData`; otherwise add the stub): raw throttle 1000 gives `reverse = 1`, 1050 or more gives 0.
